# Changelog

## 5.0.0 (Unreleased)

### Breaking Changes

**Requirements**

- Requires PHP 8.4+ (needed for pdo_firebird's time zone type support).
- Requires Laravel 13.
- Requires Firebird 5. Firebird 4 and earlier are no longer tested or supported.

**Column types**

- `boolean()` creates a native `BOOLEAN` column instead of `CHAR(1)`. Boolean columns are returned as PHP `bool`. Existing `CHAR(1)` columns are untouched.
- `timestampTz()`, `dateTimeTz()` and `timeTz()` create `TIMESTAMP WITH TIME ZONE` / `TIME WITH TIME ZONE` columns instead of plain `TIMESTAMP` / `TIME`. Their values are returned with the zone appended, e.g. `2026-10-06 11:00:00 +10:00`.
  - **These require pdo_firebird built against a Firebird 4+ client library.** With a Firebird 3 client (e.g. Debian/Ubuntu's `libfbclient2` 3.0 packages), any query that selects or binds a time zone column fails with `Data type unknown`. If you can't upgrade the client, set `DataTypeCompatibility = 3.0` in the server's `firebird.conf`, or avoid the `*Tz()` column types.
- `float()` respects its precision, so the default `float('x')` (precision 53) creates a double precision column instead of single precision `FLOAT`.
- `binary()` with a length creates `BINARY(n)` (`fixed: true`) or `VARBINARY(n)` instead of a blob.
- `json()` and `jsonb()` create `BLOB SUB_TYPE TEXT` columns instead of `VARCHAR(8191)` (and `VARCHAR(8191) CHARACTER SET OCTETS` for `jsonb()`), so JSON is no longer limited to 8191 characters.
- `useCurrent()` defaults to `LOCALTIMESTAMP` for non time zone columns and `CURRENT_TIMESTAMP` for time zone columns. Since Firebird 4, `CURRENT_TIMESTAMP` returns a time zone aware value.

**Auto-increment columns**

- `id()`, `increments()` and the other `*Increments()` columns create a `GENERATED BY DEFAULT AS IDENTITY` primary key. Previously they created a plain `NOT NULL` column that was neither auto-incrementing nor a primary key.

**Constraint and index names**

- Index, unique and foreign key names are no longer truncated to 31 characters (Firebird 4+ allows 63).
- Foreign key names are now quoted, matching unique and index names, so they are case-sensitive. Foreign keys created by earlier versions were stored in uppercase. Drop those by their uppercase name, e.g. `$table->dropForeign('ORDERS_USER_ID_FOREIGN')`.
- Indexes and constraints created by earlier versions with names longer than 31 characters were truncated, so they must be dropped by their truncated name.
- `primary()` names the constraint (e.g. `users_id_primary`) instead of letting Firebird generate an `INTEG_*` name.

**Unsupported operations now throw**

These previously generated invalid SQL or silently did nothing, and now throw a `LogicException`:

- Renaming tables (`Schema::rename()`) and indexes (`renameIndex()`).
- Stored generated columns (`storedAs()`). Use `virtualAs()` instead.
- Changing enum columns or column collations with `change()`.

**Other**

- `restrictOnDelete()` / `restrictOnUpdate()` compile to `NO ACTION`, as Firebird has no `RESTRICT` action (they behave the same).
- `Schema::getForeignKeys()` reports Firebird's `RESTRICT` rule (its default) as `no action`.
- Removed the unused `compileColumnListing()` schema grammar method. Use `Schema::getColumnListing()`.

### Added

- `Schema::dropAllTables()` and `Schema::dropAllViews()`, so `migrate:fresh` and `db:wipe` work. Previously they threw an exception.
- `Schema::getViews()` and `Schema::hasView()`.
- `dropColumn()`, `dropPrimary()`, `dropUnique()` and `dropIndex()`. These previously did nothing.
- `change()` for altering a column's type, default and nullability. Only the attributes that differ from the existing column are altered.
- Full `Schema::getColumns()` details (type, nullability, default, auto-increment, collation, comment, generation), plus `Schema::getIndexes()`, `Schema::getForeignKeys()` and `Schema::hasIndex()`.
- Column and table comments (`->comment()` and `$table->comment()`), which were previously ignored. `Schema::getTables()` returns table comments.
- `startingValue()` / `from()` on auto-increment columns (`START WITH`).
- `tinyText()`, `year()` and `virtualAs()` (computed) columns.

### Fixed

- Column modifiers are compiled in the order Firebird expects. A non-nullable column with a default (`NOT NULL DEFAULT ...`), a collation, or an enum with a default previously produced invalid SQL.
- Adding several columns in one `Schema::table()` call added every column once per column, failing with a duplicate column error.
- `renameColumn()` used invalid syntax.
- `dropForeign()` failed for foreign keys with names longer than 31 characters.
- `Schema::dropIfExists()` ignored the table prefix when checking whether the table exists.
- Single quotes in defaults, enum values and table names are escaped.
